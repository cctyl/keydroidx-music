nightlight 设计定位：为什么「锁屏歌词」要由音乐 App 自己做？

  • 生态中 Launcher 的「锁屏」只是 DevicePolicyManager.lockNow() 调起的 系统 Keyguard，无法自绘界面，因此歌词锁屏必须由音乐 App 提供一个全屏页叠加在系统锁屏之上。
  • 实现方式：LyricLockScreenActivity : KeydroidxBaseActivity，开启 setShowWhenLocked(true) + setTurnScreenOn(true)，全屏沉浸、复用生态顶栏/软键/点阵字体与主题。
  • 数据零成本：歌词行直接取 PlaybackStateManager.getCurrentLyricLineSync()（LrcParser 解析），桌面侧也已有 content://io.github.cctyl.keydroidx.music.playback/state 的 lyric_text 列可复用。

route 三种落地路径（建议 A）

check_circle 方案 A · 音乐 App 自绘锁屏页推荐

新建 ui/LyricLockScreenActivity.kt，继承 KeydroidxBaseActivity。沉浸全屏 + 大时钟 + 大字歌词，setShowWhenLocked/setTurnScreenOn 叠加系统锁屏。改动最小、样式最可控、主题字体自动跟随。

方案 B · Launcher 侧新增「歌词锁屏」组件 / 页面

复用现成数据通道 content://io.github.cctyl.keydroidx.music.playback/state（lyric_text 列已实现）与 KeydroidxMusicSessionReader 三级取数策略。好处是待机屏直出歌词、无需启动音乐进程；代价是要改 Launcher，且仍无法覆盖系统 Keyguard。

方案 C · 系统媒体通知承载歌词行

借 MediaSession 通知的副标题显示当前歌词行。零新增界面，但受系统通知样式/权限限制（锁屏通知可被关闭），仅适合做兜底，不满足本案诉求。

warning 视觉与规范自查

  • 字号全部落在 @dimen/keydroidx_font_* 语义区间（大时钟 display 档、歌词 body/title 档、副信息 caption 档），无裸写字号。
  • 高亮当前歌词不用 bold（避免 ≤13sp 点阵字加粗像素粘连），改用「加大字号 + 主题色 + 发光 + 左右竖线」表达。
  • 软键栏三段等宽，空位用 INVISIBLE 占位（HTML 中用 visibility:hidden 等价模拟），绝不用 GONE。
  • 歌词区上下留 2 行「幽灵行」占位，保证高亮行始终垂直居中、切行时不跳动。
  • 封面旋转仅在播放态运行，暂停时停在原位（animation-play-state: paused）。

需要你拍板的 4 个点：

  1. 归属：这套锁屏歌词放 音乐 App（方案 A）还是 Launcher（方案 B）？
  2. 是否需要「点亮屏幕」——即熄屏时按键自动亮屏并弹出歌词锁屏？
  3. 是否需要「歌词偏移 ±0.5s」微调（各平台歌词常有偏移，按键机调起来费劲）？
  4. 锁屏页是否要接管音量键（UP/DOWN 当前设计为浏览歌词，音量改到长按）？
